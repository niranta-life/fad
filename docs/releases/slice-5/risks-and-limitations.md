# Risks and limitations

- This repository has no `.github` workflows. The CI run ID is unset. `npm test` is not that run.
- A 40-call local evaluate loop on the rebuilt image measured p50 2.9 ms and p95 4.98 ms. That sample met 100 ms. It is one client and one container, not a capacity test. Slice 3 `PERF-01`, `PERF-02`, and `PERF-03` stayed `NOT RUN`. The earlier sample on `sha256:a05a932e…` is unchanged in `performance-evidence/evaluate.json`.
- `deploy/k8s/policy-overlay.yaml` is a documented overlay. No cluster was available, so `kubectl apply` was not run.
- A production-mode container against `fad-s0-pg` exited because that Postgres has no TLS. The startup message was `The server does not support SSL connections`. The flag-off smoke used development cleartext on the same image. Production TLS on this database is BLOCKED. The rebuilt image repeated that result in `deployment-evidence/production-tls-after-match.txt`.
- Image `sha256:a05a932ef2bbd271bd6b07b06ea778a9828dcf9ce5e1735dd41077ad4413f3b0` was created at 2026-10-21T14:44:19-07:00, before the UUID and invalid-tag source change. The image was rebuilt as `sha256:45fbe99e5656fdac4a3f07b703c356684c6520769bf252708ab70de122f48ba8` at 2026-10-21T15:23:24-07:00. Flag-off, the production TLS boot, flag-on staging, the 40-call evaluate sample, and the previous-image check were repeated against that image. Staging request ids are in `deployment-evidence/staging-after-match.json`. The repeated previous-image result is `deployment-evidence/previous-image-after-match.json`.
- `FAD_POLICY_WRITE_BODY_MAX_BYTES` is the body-limit setting. The active-policy ceiling is the constant 256. The environment names in the package operations note are not read, and the ceiling cannot be raised by configuration.
- The down script is not applied by the migrator and was not run against the shared database. Rollback of the feature is the previous image with the tables kept.
- Evaluation does not change authorization of existing REST or MCP operations. An allow does not invoke an agent.
- `agent_tag_tombstone` rejects object and array tag values, so `{"v":"high"}` cannot be stored. Evaluation returns 503 and writes no decision when a referenced assignment is not a string, boolean, or integer. The HTTP proof used stored `1.5`. The unit proof covers objects, arrays, null, and `1.5`.
- A sequential tag removal changed the next input digest (`STATE` in the journey). An uncommitted tag update is invisible to the next evaluation because the evaluator reads inside its own transaction. A pause inside that transaction, with a commit landing between the tag read and the decision insert, was not injected.
- MCP `if_match` omitted is rejected by the client from the server schema before a write (`FadMcpProtocolError`). The server still requires `If-Match` and returns `REVISION_CONFLICT` for a stale tag. Both left the revision unchanged.
- `tests/slice4.test.mjs` COMP-03 no longer shells `git diff` against the Slice 4 parent for the SDK tree. It checks that the previous SDK surfaces remain in source. COMP-10 expects `@fad/sdk` 0.5.0 and `@fad/mcp-client` 0.2.0. Those assertions were updated so the historical suite accepts this additive release.
- Zod's string maximum counts UTF-16 code units. The service counts Unicode code points and is the authority for persisted names.
- `fad_bootstrap` retains `BYPASSRLS` because Slice 0 uses it for bootstrap. `fad_app` does not. The API runtime role is `fad_app`.
